## CIC-IDS-2017 requirements

- One Tuesday PCAP and one Friday PCAP. Add Monday only when D4 benign HTTP fallback is required.
- CIC flow-label CSV files with `Timestamp`, `Label`, `Source IP`, and `Destination IP`.
- If a day is split into multiple PCAPs, merge them with `mergecap` before `dataset-prep`.

## Safety

MTA PCAPs can contain live malware samples. Extract them only in an isolated dataset VM, copy only PCAPs into `data/datasets/mta/`, and never copy PCAPs or samples into the deployment image.

## Current verification status

- `uv run pytest -q` passes, including the new dataset, runtime, and all-detector inference tests.
- Real inputs are present: UWF CSV (10 MB / 0.6 MB), CIC Tuesday/Friday PCAP (11 GB / 8.3 GB), 11 MTA PCAPs, and GraphTunnel (234 MB).
- A sampled full UWF Parquet week is also **conn-only** (50,444 rows, 27 columns); it has no `ssh/http/files/ssl/smb/dns` logs, so full UWF does not solve D3/D4/D6/D7.
- `dataset-prep` produced D1=72, D2=78, D3=12, D4=12, D5=51, D6=12, D7=36 runs.
- `dataset-train` completed. Synthetic D6 is strong. Public-data metrics remain limited: D2 test recall is 0.0; after fixing the over-conservative `ensure_above_benign` guard, D3 reaches recall 1.0 but 1152 FP/day and D4 reaches recall 1.0 but 4320 FP/day on their small public test splits (both PR-AUC 0.667); D5 recall is 0.003 with 69 FP/day; D7 improved to recall 0.845, precision 0.833, FP 355/day after using CIC benign DNS and a higher threshold.
- A real-model Docker image `ndr-ml:0.2.0` was built and smoke-tested with D3/D7 run fixtures: all seven detector files and `alerts.jsonl` were produced (9 alerts across the two fixtures after the D7 model/ threshold change).
- A real-model live `ndr infer --raw` run on a 10-minute CIC Tuesday slice produced 45 fused alerts with the earlier models; this confirms the runtime path but also confirms the thresholds are not lab-calibrated.
- Target ML VM transfer, `run-infer.sh` cron execution, and `--export-elk` against the lab Elasticsearch were not run because `ML_HOST` and ELK credentials/CA are not available here.

## Active project artifact (synthetic demo profile)

The local `models/` directory and `dist/ndr-ml-0.2.0.tar.gz` now contain the **synthetic prelab models** generated by:

```bash
uv run ndr prelab-demo --workdir /tmp/ndr-prelab-final --seed 42
```

This is deliberate for the course project demo: synthetic held-out metrics are D2/D3/D4/D5/D6/D7 recall `1.00`, test FP/day `0.00`; D1 keeps its unsupervised train alert rate. The public-data models and their weak metrics above are retained as the domain-shift baseline, not as the live demo artifact.

The demo Docker smoke test with synthetic D3/D7 fixtures produced:

```text
D1=1, D2=1, D3=1, D4=0, D5=1, D6=0, D7=6
total_detections=10, total_alerts=3
```

These numbers must be presented as **synthetic validation**, not lab or production performance.

## D7 wildcard and unknown-tunnel supplement

Downloaded the remaining GraphTunnel hard-negative/generalization sets:

```text
data/datasets/graph-tunnel/wildcard/*.pcap          13 PCAP
data/datasets/graph-tunnel/unkownTunnel/**/*.pcap   17 PCAP
```

Materialized them as:

```text
data/runs/d7-wildcard/   13 benign wildcard runs
data/runs/d7-unknown/    17 unknown-tunnel attack runs
```

D7 training variants (min_events=1):

| Train benign | Test recall | Test FP/day | Unknown tunnel runs caught |
|---|---:|---:|---:|
| GraphTunnel normal | 0.972 | 1264 | 14/17 |
| GraphTunnel normal + wildcard | 0.972 | 25413 | 14/17 |
| GraphTunnel normal + wildcard + CIC benign | 0.845 | 345 | 8/17 |
| CIC benign | 0.845 | 110 | 8/17 |
| GraphTunnel normal + CIC benign | 0.845 | 110 | 8/17 |

Conclusion: with the current 26 DNS features, adding `wildcard` as training benign makes FP substantially worse; it should be used as an evaluation hard-negative, not as training benign. CIC benign reduces FP but misses more unknown tunnel tools. D7 is still not production-ready; it needs target benign calibration and better features/thresholding.

### D7 feature expansion attempt

An 11-feature expansion was tried: query length/entropy/label standard deviations, qtype A/AAAA/CNAME/MX/other ratios, answer count max/zero ratio, and subdomain novelty. It did not improve generalization:

```text
normal_tunnel: recall 0.718, FP 0/day, unknown covered 2/17
cic_tunnel:    recall 0.718, FP 0/day, unknown covered 2/17
```

This was worse than the existing v0.3 feature set (unknown covered 8/17 with CIC benign), so the expansion was reverted. D7 production remains blocked on target benign calibration and better unknown-tunnel generalization.
